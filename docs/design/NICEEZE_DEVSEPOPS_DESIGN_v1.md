## 2-2. OCR 2段階PIIフィルタの詳細フロー

```
                    [原票画像 INPUT]
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  STAGE 1: 構造的PIIフィルタ（決定論的・ルールベース）          │
│                                                             │
│  正規表現パターン:                                           │
│  ・電話番号: r'0\d{1,4}-\d{1,4}-\d{4}' → HASH(下4桁保持)   │
│  ・郵便番号: r'\d{3}-\d{4}' → 保持（非PII）                 │
│  ・メール:   r'[\w.-]+@[\w.-]+\.\w+' → ドメインのみ保持      │
│  ・クレカ番号: r'\d{4}[-\s]\d{4}[-\s]\d{4}[-\s]\d{4}' → ** │
│                                                             │
│  固有表現認識（spaCy ja_core_news_lg）:                      │
│  ・PERSON（人名）→ SHA-256(name + salt) に置換               │
│  ・ORG（組織名）→ SHA-256(org + salt) に置換（配送業者除く）  │
│  ・LOC（住所）→ 都道府県・市区町村まで保持 / 番地以降を[ADDR]  │
│                                                             │
│  出力: Stage1_filtered_text（PIIリスク大幅低下）             │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  STAGE 2: LLMベースPII検証フィルタ（確率論的・文脈認識）       │
│                                                             │
│  プロンプト設計:                                             │
│  「以下のテキストを分析し、残存するPIIを検出せよ。             │
│   検出されたPIIは [REDACTED_TYPE] に置換すること。           │
│   荷物追跡番号・配送業者名・日付は保持してよい。              │
│   JSON形式で出力: {cleaned_text, pii_detected: []}」        │
│                                                             │
│  モデル: Claude Haiku（コスト最適）                           │
│  入力: Stage1_filtered_text                                 │
│  出力: Stage2_anonymized_text + pii_audit_log               │
│                                                             │
│  FinOps最適化:                                              │
│  ・max_tokens: 500（荷物情報の構造化に十分）                  │
│  ・キャッシュ: 同一伝票番号は24時間キャッシュ                  │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  STAGE 3: 構造化データ抽出（Claude Sonnet / GPT-4o）         │
│                                                             │
│  INPUT: Stage2_anonymized_text（PIIゼロ保証）                │
│                                                             │
│  抽出項目:                                                  │
│  ・tracking_no（追跡番号）                                   │
│  ・carrier（配送業者: ヤマト/佐川/日本郵便等）               │
│  ・estimated_delivery（配達予定日時）                        │
│  ・redelivery_time_slot（希望再配達時間帯）                  │
│  ・package_type（荷物種別: 宅配便/ゆうパック等）              │
│                                                             │
│  OUTPUT: packages テーブルへINSERT（RLS適用）                │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
                    [DB INSERT 完了]
```

## 2-3. 暗号化キー管理（KMS設計）

```
GCP KMS 鍵リング構成:
  niceeze-keyring
    ├─ user-pii-key         (AES-256-GCM / 自動ローテーション: 90日)
    │    └─ 用途: users.email/name/phone の暗号化
    ├─ package-addr-key     (AES-256-GCM / 自動ローテーション: 90日)
    │    └─ 用途: packages.address_encrypted の暗号化
    ├─ ocr-temp-key         (AES-256-GCM / 自動ローテーション: 30日)
    │    └─ 用途: OCR一時ファイルの暗号化（GCS CMEK）
    └─ audit-log-key        (AES-256-GCM / 自動ローテーション: 365日)
         └─ 用途: 監査ログの署名・検証

アクセス制御:
  ・Cloud Run Service Account → user-pii-key: ENCRYPT_DECRYPT
  ・OCR Worker Service Account → ocr-temp-key: ENCRYPT_DECRYPT
  ・Admin Service Account → 全鍵: DECRYPT のみ（緊急時）
  ・開発者 → KMSへの直接アクセス: 禁止（IAM Conditions）
```

| 管理項目 | 実装内容 | 証跡 |

## 2-5. データ保護影響評価（DPIA）サマリー

```
リスクレベル: 中（配送情報は高感度ではないが、住所情報を含む）

リスク1: OCR処理中のPII漏洩
  対策: 2段階フィルタ + メモリ処理のみ（永続化禁止）+ 24h TTL
  残存リスク: 低

リスク2: DB不正アクセスによるPII大量流出
  対策: RLS全テーブル + AES-256暗号化 + 暗号キーのKMS分離
  残存リスク: 極低（暗号キー奪取なしに解読不可）

リスク3: LINE APIを通じたPII誤送信
  対策: PUSH通知に氏名・住所を含めない（荷物番号のみ）
  残存リスク: 極低

リスク4: LLMへのPII入力（Stage3のClaude/GPT）
  対策: Stage1/2で匿名化完了後にのみLLM送信
  残存リスク: 低（匿名化済みテキストのみ送信）
```
