## iOS技術的制約 詳細（B案の壁）

### 制約1: WebXR on Safari iOS — 実装可能だが条件付き

```
Safari iOS 16+（2022年9月〜）でWebXR Hit Test APIが対応。
  ✅ iOS 16.4以上: WebXR Session / Hit Test 動作確認済
  ⚠️ iOS 15以下: WebXR未対応 → フォールバック必須
  ⚠️ LINE LIFF（WKWebView）: WebXR未対応
       → 判断⑥Aの「PWA別URL」で対応済（B案でも同じ対処）
```

**日本のiOSバージョン分布（2026年推定）**:
```
iOS 17+ : 約65%
iOS 16  : 約20%
iOS 15以下: 約15%（WebXR非対応）
```
→ B案採用時、iOS 15以下のユーザー（約15%）には手動入力フォールバックが必要。

### 制約2: WKWebView（LINE LIFF） — iOS/Android共通制約

```
iOS/Android いずれも LINE LIFF 内の WKWebView / WebView では WebXR 動作しない。
→ 判断⑥A（PWA別URL）で両案とも同じ対処済。B案でもこの制約は変わらない。
```

### 制約3: ARKit vs ARCore — 実装差分

```
ARCore（Android）: WebXR Hit Test が最も安定。
  ✅ 平面検出精度: ±10〜20cm（±50cm許容に対し余裕あり）
  ✅ Chrome Androidで標準対応（追加設定不要）

ARKit（iOS）: Safari WebXR は「immersive-ar」モードが追加作業必要。
  ⚠️ iOS では navigator.xr.requestSession('immersive-ar') の権限要求UXが異なる
  ⚠️ ARKit平面検出は高精度だが、実装コードのiOS固有テストが必要
  ⚠️ Safari更新ポリシーによるAPI変更リスク（Appleの裁量）
```

### 制約4: iOS固有テスト工数

```
B案採用時の追加作業:
  ① iOS実機（iPhone）での Safari WebXR 動作確認: 1日
  ② ARKit Hit Testの精度検証（±50cm以内確認）: 1日
  ③ iOS 15フォールバック UI実装（「AR非対応 → 手動入力」案内）: 0.5日
  ④ iOS固有UX差分対応（権限要求フロー）: 0.5〜1日
  合計追加: 3〜4人日
```

## Gate影響分析

### A案（Android優先）— G1完了維持

```
WebXR実装計画（G1内）:
  Week 1: WebXR Hit Test API実装（Android Chrome）    … 3日
  Week 2: ±50cm精度テスト + PWA別URL設定              … 2日
  Week 3: LIFF→PWA導線（案内文/QRコード）             … 1日
  Week 4: 結合テスト + バッファ                       … 1日
  合計: 7日 → G1（2026/09末）内に完了可能

DXFインポートと合わせた総工数: 7(AR) + 4(DXF) = 11日
G1残スコープに収まる見込み: ✅
```

### B案（iOS/Android同時）— G1への影響あり

```
追加3〜4日により:
  ・G1内に収める場合: 他タスクを圧迫（TMS-SET-001本体実装との競合）
  ・G1後ろ倒しリスク: 1〜2週間（2026年10月上旬）

リスク要因:
  ① iOS実機テスト環境の準備（実機が必要）
  ② Appleの突発的なSafari API変更（Appleの裁量でAPIが変わる可能性）
  ③ ARKit固有バグへの対処工数が読みにくい

判定: G1完了を厳守する場合 B案はリスクあり
    G1を1〜2週間延長容認する場合 B案は実現可能
```

## 自律COOとしての推奨案

**推奨: A案（Android優先） — ただし条件付きでB案も選択可**

### 推奨理由（A案）

```
① G1完了（2026/09末）を守ることが最優先。Gate制厳守はCEO絶対ルール。
② ARコア機能（DXF自動抽出）が主目的。ARはあくまで補助計測ツール。
③ Android先行リリース後、G2期間（〜2026/11末）中にiOS追加対応が可能。
   G2の15ヶ国語i18nと並行してiOS対応を追加できる。
④ iOSユーザーは判断⑥Aの「手動入力PWAフォールバック」で対処できる。
   AR非対応 = 使えないではなく、AR非対応 = 手動入力 という上位互換UI。
```

### B案が推奨される条件

```
以下の条件を全て満たす場合、B案も合理的:
  ① G1完了を2026/10上旬まで1〜2週間延長することをCEOが承認する場合
  ② TMS-SET-001の配送スタッフの大多数がiPhoneユーザーである場合
  ③ iOS実機テスト環境（iPhone）が準備可能な場合
```
